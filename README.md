# Semantic Search — CalmFruits

Проект семантического поиска товаров в постановке `query-to-item`.

Автор: Александр Рогов.

## Итог проекта

В проекте сравнены лексический TF-IDF baseline, базовый семантический поиск на `paraphrase-multilingual-MiniLM-L12-v2`, retrieval-модель `intfloat/multilingual-e5-base` и гибридный подход.

Финальной конфигурацией выбран гибрид:

`0.75 × E5 + 0.25 × TF-IDF`

На независимой test-выборке из 300 запросов он показал:

- NDCG@5 = 0.2909;
- NDCG@10 = 0.3487;
- Recall@10 = 0.4369;
- MRR@10 = 0.2460;
- HitRate@10 = 0.5700.

Test использовался один раз после завершения настройки на validation.

## Данные

Для запуска Streamlit необходим исходный файл:

`wb_products_raw_sample.parquet`

Файл данных не хранится в Git-репозитории и должен быть помещён в корневую папку проекта.

По умолчанию приложение ищет:

```text
./wb_products_raw_sample.parquet
```

При необходимости путь можно изменить через переменную окружения:

```text
RAW_PRODUCTS_PATH=/path/to/wb_products_raw_sample.parquet
```

## Подготовка каталога в приложении

Streamlit использует ту же базовую подготовку каталога, что и notebook:

1. выбираются корневые категории `Одежда` и `Обувь`;
2. поиск выполняется на уровне `imt_id`;
3. при нескольких строках одного `imt_id` сохраняется строка с наиболее длинным `description`;
4. карточки без `imt_name` и `description` исключаются;
5. формируется `product_text = imt_name + subj_name`;
6. TF-IDF обучается с `ngram_range=(1, 2)`, `max_features=50000`, `sublinear_tf=True`;
7. E5 использует префиксы `query:` и `passage:`;
8. скоры TF-IDF и E5 нормализуются min-max отдельно для каждого запроса;
9. итоговый score рассчитывается как `0.75 * E5 + 0.25 * TF-IDF`;
10. при равных score применяется детерминированный tie-break по `imt_id`.

## Установка

Рекомендуется Python 3.10+.

```bash
pip install -r requirements.txt
```

## Запуск Streamlit

```bash
streamlit run streamlit_app.py
```

После запуска откроется локальная страница Streamlit.

## Первый запуск

При первом запуске приложение автоматически создаёт локальные артефакты в папке:

```text
streamlit_artifacts/
```

В неё сохраняются:

- подготовленный каталог;
- TF-IDF vectorizer;
- TF-IDF matrix;
- E5 embeddings полного подготовленного каталога.

Расчёт E5-эмбеддингов при первом запуске может занять несколько минут. При следующих запусках артефакты загружаются с диска.

Папка `streamlit_artifacts/` не должна добавляться в Git.

## Интерфейс

Пользователь вводит поисковый запрос и выбирает число результатов. Для каждой найденной карточки отображаются:

- позиция в выдаче;
- название товара;
- предметная категория;
- бренд, если он указан;
- `imt_id`;
- краткое описание;
- по желанию — Hybrid, E5 и TF-IDF score.

## MLflow

Эксперименты сохранены в MLflow в эксперименте `wb-semantic-search`.

Создано 8 успешных run для validation и финального test. Для каждого run сохраняются параметры, метрики, таблицы по запросам, графики и evaluation-артефакты.

Проверка:

```bash
python check_mlflow.py wb-semantic-search --min-runs 8
```

Параметры подключения к MLflow должны храниться в локальном `.env`. Файл `.env` не добавляется в Git.

## Ограничения

Основная оценка качества проводилась на пуле асессоров из 4 256 карточек, тогда как Streamlit выполняет поиск по полному подготовленному каталогу. Разметка является неполной: неоценённые товары технически получают `relevance = 0`, даже если содержательно подходят запросу.

Запросы в учебной разметке синтетические, поэтому перед промышленным внедрением необходима дополнительная проверка на реальном поисковом трафике.
